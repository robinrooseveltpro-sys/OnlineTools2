What is a cron expression?

A cron expression is a compact schedule used to specify when recurring jobs should run. Developers and system administrators use cron schedules for tasks such as database backups, cleanup scripts, reports, scheduled API calls, maintenance jobs, and automated data processing.

A standard Unix cron expression contains five time-and-date fields in this order: minute, hour, day of month, month, and day of week. Each field restricts the values that can trigger a job. Special characters such as asterisks, commas, hyphens and slashes let you build recurring schedules without listing every time individually. citeturn424184search0 

minute hour day-of-month month day-of-week

*/15 9-17 * * 1-5

The example above selects every 15th minute, during hours 9 through 17, from Monday through Friday. The parser expands the fields and shows concrete upcoming times, making it easier to catch unexpected scheduling behavior before deploying a job.

Special characters in cron syntax

Symbol Meaning Example
* Select every allowed value in that field. * * * * *
, Select multiple values. 0,30 * * * *
- Select an inclusive range. 0 9-17 * * *
/ Select values at a specified step interval. */10 * * * *

Day-of-month and day-of-week: an important cron rule

One common source of cron scheduling errors is assuming the day-of-month and day-of-week fields always need to match simultaneously.

In standard Unix cron, when both fields are restricted rather than written as a plain wildcard, the job normally runs when either field matches. For example: 

0 9 1 * 1

This can run at 09:00 on the first day of a month and on every Monday, rather than only on a Monday that falls on the first of the month. That behavior matters when planning monthly billing tasks, reports, maintenance, or other business-critical jobs. citeturn424184search0

Remember: cron syntax can vary across implementations. This page uses the standard five-field Unix interpretation for this day rule; always confirm the target scheduler's documentation before relying on a complex schedule.

Cron time zones and upcoming run times

A cron schedule is interpreted using the scheduler's clock and configuration. The time displayed on your laptop or phone may differ from the time used by a server, container, or cloud scheduler. The parser shows the next runs in your browser's local time zone and includes a UTC equivalent to help you compare them.

Daylight-saving transitions can also affect local-time schedules. Some local times do not occur on the spring transition, while some occur twice when clocks move backward. Scheduling platforms may handle these cases differently, so do not treat this preview as a guarantee of exact production behavior. citeturn424184search0

When troubleshooting a job that runs too early or too late, verify the scheduler's configured time zone, the server clock, the expression itself, and any platform-specific scheduling defaults.

Frequently asked questions

What does a cron expression parser do?

It reads cron schedule syntax, checks the individual fields, explains the schedule in understandable terms, and can calculate upcoming times that match the expression.

Is this cron expression parser free?

Yes. You can parse and inspect supported expressions, view upcoming scheduled run times, copy the report, and download it without paying or creating an account.

Which cron expression format does this tool support?

It supports the standard five-field Unix cron format: minute, hour, day of month, month, and day of week. It also supports common aliases including @yearly, @annually, @monthly, @weekly, @daily, @midnight, and @hourly. Six-field seconds formats and Quartz-specific operators are not supported.

What does */5 * * * * mean?

It means that the scheduled job matches every five minutes: minute 0, 5, 10, 15, and so on through each hour.

How do I schedule a task Monday through Friday at 9 AM?

A common Unix cron expression for this is 0 9 * * 1-5. It selects minute zero, hour nine, every day of the month, every month, and weekdays Monday through Friday.

Does the parser support month and weekday names?

Yes. It supports three-letter month names such as JAN and DEC, as well as weekday names such as MON and FRI. Names can be used in lists and inclusive ranges.

Why are day-of-month and day-of-week sometimes treated as OR?

Standard Unix cron normally uses OR when both of those fields are restricted. This means either matching the specified day of the month or matching the specified weekday can trigger the job. Different scheduler implementations may have different rules, so check the relevant documentation.

Why doesn't my cron expression work in this tool?

Check that the expression contains five fields, each field uses valid values for its position, lists and ranges are correctly written, and the expression does not use an unsupported extension. A six-field expression containing seconds, Quartz operators, or a startup-only alias may not be compatible with this parser.

Are the next run times guaranteed to match my server?

No. The preview uses your browser's local date and time handling. The actual scheduler may use another time zone or different syntax and daylight-saving rules. Compare the UTC output and the target scheduler's configuration before deploying important jobs.

Does this tool send my expression to a server?

The parser and date calculations run in your browser. The cron expression is not sent to a validation API by this page. The page may still load the site's shared stylesheet and JavaScript files.

Can I use the result with Kubernetes or GitHub Actions?

Both systems use cron-like scheduling, but scheduler behavior and supported extensions can differ. Confirm the required syntax, time zone, and any platform-specific rules before copying an expression into a production configuration.
